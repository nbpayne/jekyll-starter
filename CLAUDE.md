## Commands

**Install dependencies (first time):**
```sh
bundle install       # Jekyll and Ruby gems
yarn                 # Node/Gulp dev tools
bower install        # Client-side JS/CSS (Bootstrap, jQuery)
```

**Development (build + serve + watch):**
```sh
gulp                 # Full build, start Jekyll with livereload, watch for changes
```

**Build only (no serve/watch):**
```sh
gulp build
```

**Watch CSS/JS only (Jekyll already running):**
```sh
gulp liveReload
```

Site is served at `http://127.0.0.1:4000` with `--livereload`, `--drafts`, and `--future` flags.

## Build pipeline

The Gulp pipeline has a specific order that matters:

1. **`clean`** — deletes `_includes/head.html`, `_includes/foot.html`, `css/**/*`, `js/**/*`
2. **`css`** — compiles `__sass/**/*.scss` → `css/` (unminified + `.min.css` with sourcemap)
3. **`wireDependencies`** — runs `wiredep` on `__includes/*.html` to inject bower deps into `<!-- bower:* -->` blocks
4. **`lintJS`** — ESLints `__js/**/*.js`
5. **`js`** — reads `__includes/*.html`, processes `<!-- build:js -->` blocks via `useref`, uglifies JS → `js/`, copies HTML → `_includes/`
6. **`jekyllServe`** — spawns `jekyll serve`

### Source vs. output directories

| Write here | Gets built to |
|---|---|
| `__sass/` | `css/` |
| `__js/` | `js/` (as `app.min.js`) |
| `__includes/` | `_includes/` (after wiredep + useref) |
| `bower_components/` | `js/vendor.min.js`, `js/bootstrap.min.js` |

Never edit files in `css/`, `js/`, or `_includes/head.html` / `_includes/foot.html` directly — they are regenerated on every build.

## Jekyll structure

- `_layouts/` — page layouts (Liquid templates)
- `_includes/` — partials included by layouts; `head.html` and `foot.html` are generated by Gulp
- `_config.yml` — site config; requires Jekyll restart to take effect
- `_site/` — Jekyll build output; not committed
- Content pages are Markdown files at the repo root (`index.md`, `about.md`, etc.)

## JS dependencies

Bower manages client-side dependencies (`bower.json`): Bootstrap 5 and jQuery. The `__includes/foot.html` uses `<!-- build:js -->` / `<!-- bower:js -->` / `<!-- endbuild -->` comment blocks that `wiredep` and `useref` parse to bundle vendor scripts.

## ESLint

Config is in `eslint.config.js` (flat config format). Rules enforce: 2-space indent, single quotes, semicolons, `===`, curly braces required, trailing commas in multiline. Linting runs automatically as part of the Gulp build and will fail the build on errors.
